# How Privacy Overlay Works

Privacy Overlay is designed to be a fast, production-grade, stealthy utility application for macOS. It bypasses standard window management constraints to provide a persistent, floating rich-text environment.

## 1. The Core Architecture (AppKit & SwiftUI)
The application is built using a hybrid approach:
* **AppKit (NSPanel):** Standard macOS windows disappear when you click outside of them or change applications. To solve this, we use an `NSPanel` configured with `.floating` and `.nonactivatingPanel` behaviors. This ensures the window stays stubbornly on top of all other applications (like VS Code or Zoom) and allows you to type into it without stealing the active focus from your background applications.
* **SwiftUI:** The user interface inside the panel is rendered using SwiftUI for modern, declarative layout management.
* **Global Hotkeys:** We use `NSEvent.addGlobalMonitorForEvents` combined with `CGEvent` keyboard taps to listen for `Cmd + Shift + O` globally, allowing you to instantly toggle the overlay from anywhere in the system.

## 2. Syntax Highlighting Engine
Standard SwiftUI `TextEditor` components do not support live syntax highlighting or rich text colors very well. 
* To solve this, we wrapped a native AppKit `NSTextView` in an `NSViewRepresentable` struct.
* On every keystroke, a custom `SyntaxHighlighter` scans the text using Regular Expressions (RegEx) to identify keywords (like `let`, `mut`, `String`, etc.).
* It applies native `NSAttributedString` colors (using `NSColor`) to ensure the text remains vibrant and highly readable against the dark, glassmorphic background, regardless of the user's macOS system theme.

## 3. Real-Time Collaboration (Firebase)
To support real-time pair programming and text sharing, we integrated Firebase Firestore.

### Why Firebase?
Firebase provides ultra-low latency websocket connections. When a colleague types a character in Mumbai, it reflects on your Mac in milliseconds. 

### The Engineering Shortcut (REST API vs SDK)
Traditionally, adding Firebase to an Apple application requires downloading and compiling massive C++ SDKs. Because this project is built using lightweight Command Line Tools (`swiftc`), installing the official SDK would bloat the build times to 10+ minutes and introduce severe dependency complexities.

* **The Solution:** We entirely bypassed the Firebase SDK in the Mac app.
* **How it works:** The Mac app communicates directly with the **Firestore REST API** using Apple's native `URLSession`. 
* When you click "Sync", it generates a random 4-digit room code and begins a lightweight polling sequence (every 1.5 seconds) to fetch changes via JSON. When you type, it issues a `PATCH` request to update the Firestore document.
* This results in **0 third-party dependencies**, instant compile times, and an incredibly lightweight `.app` bundle.

### The Web Portal
The Web Portal (`index.html`) is a standalone static web application. Unlike the Mac app, the web portal *does* use the official Firebase JavaScript modular SDK to achieve instant WebSocket synchronization. 
* Your colleague enters the random 4-digit room code generated by your Mac app.
* The web portal subscribes to the Firestore document for that specific room.
* All data is synchronized seamlessly between the `URLSession` REST API on the Mac and the JS SDK on the web.

## Security & Privacy
* **Ephemeral Rooms:** Room codes (1000-9999) are randomly generated and ephemeral. If a room code collision occurs across different days, the data is simply overwritten.
* **Strict Opt-In:** Syncing is strictly disabled by default upon application launch to prevent accidental keystroke broadcasting.
* No sensitive API keys or environment variables are stored in plaintext in the open documentation.
